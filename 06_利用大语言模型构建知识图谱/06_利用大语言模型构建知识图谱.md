在本章中，你将探索如何利用大语言模型（LLMs）从文本文档等非结构化数据源构建知识图谱。本章的重点是大语言模型如何从原始文本中提取并结构化数据，将其转化为可用于构建知识图谱的可用格式。

在前面的章节中，你学习了文档分块、嵌入和检索的基本技巧（第2章），以及提升检索准确率的更高级方法（第3章）。但正如你在第4章中所了解到的，在需要对数据进行结构化处理以回答需要筛选、计数或聚合操作的问题的场景中，仅依赖文本嵌入会面临挑战。为解决仅使用文本嵌入的局限性，你将学习如何利用大语言模型（LLMs）进行自动化数据提取，将非结构化数据转换为适用于知识图谱构建的结构化格式。学完本章后，你将能够从原始文本中提取结构化信息，为提取的数据设计知识图谱模型，并将这些数据导入图数据库。

## 1. 从文本中提取结构化数据

网络上乃至企业内部的大部分信息都以各类文档等非结构化格式存在。然而，在某些情况下，仅使用文本嵌入的简单检索技术效果不佳，法律文书便是其中一个典型例子。

例如，如果你询问的是与ACME公司签订的合同中的付款条款，那么务必确保这些条款确实来自该特定合同，而非其他合同。当你只是对多个法律文档进行分块并检索时，检索到的前k个分块可能来自不同且不相关的文档，这会造成混淆，如图6.1所示。

![1779974684678](images/06_利用大语言模型构建知识图谱/1779974684678.png)

图 6.1 展示了合同文件如何被拆分为文本块，并使用文本嵌入进行索引。当终端用户提出某个具体问题时，例如：在查询某一特定合同的付款条款时，系统会检索最相关的文本片段。然而，若多份合同包含不同的付款条款，检索过程可能会意外从不同文档中提取信息，将目标合同的相关片段与其他合同的无关片段混在一起。出现这种情况的原因是，系统仅基于相似度检索排名靠前的文本片段，却并非总能区分这些片段是否来自正确的合同。最终，包含“付款”“条款”等关键词但分属不同合同的片段可能被一并纳入，导致条款信息呈现碎片化且前后矛盾。当大语言模型尝试将这些混杂的片段整合成连贯答案时，这种混乱便会引发问题，最终增加输出信息不准确或具有误导性的风险。

此外，考虑以下问题：我们目前与ACME公司有多少份有效合同？要回答这个问题，你首先需要根据合同的有效状态筛选所有合同，然后对相关合同进行计数。这类查询类似于传统的商业智能问题，而文本嵌入方法在这类问题上存在不足。

文本嵌入主要用于检索语义相似的内容，而非处理数据筛选、排序或聚合等操作。要处理这类操作，需要结构化数据，因为仅靠文本嵌入并不适合完成这些任务。

对于某些领域，在实现RAG应用时，对数据进行结构化处理至关重要。幸运的是，由于对自然语言有着深刻的理解，大语言模型（LLMs）擅长从文本中提取结构化数据，能够精准识别相关信息。可以通过微调模型或借助特定提示词引导它们定位并提取所需的数据点，将非结构化信息转化为表格或键值对等结构化格式。在处理大量文档时，使用大语言模型进行结构化数据提取尤为实用——人工识别和整理这类信息不仅费力，还十分耗时。通过自动化提取流程，大语言模型能帮助企业将非结构化信息转化为可落地的结构化数据，进而用于进一步分析或RAG应用。

### 1.1. 结构化输出模型定义

从文本中提取结构化数据并非新想法，多年来它一直是数据处理中的一项重要任务。从历史上看，这一过程被称为信息抽取，需要复杂的系统，通常依赖于多个协同工作的机器学习模型。这些系统的构建和维护成本通常很高，需要一支由熟练工程师和领域专家组成的团队来确保其正常运行。由于这些原因，只有拥有大量资源的大型组织才有能力实施此类解决方案。高昂的成本和技术壁垒让许多企业难以企及，企业和个人也能受益。然而，大语言模型的技术进步极大地简化了这一流程。如今，用户只需向大语言模型发出指令，就能提取结构化信息，技术门槛大幅降低，无需再开发和训练多个模型。这一转变为结构化数据提取打开了广泛的应用场景。

利用大语言模型提取结构化数据已成为一种极为常见的应用场景，OpenAI 因此在其 API 中推出了结构化输出功能，以简化并标准化这一流程。该功能允许开发者提前定义预期的输出格式，确保模型的响应遵循特定的结构。结构化输出并非独立的库，而是 OpenAI API 的内置功能，可通过函数调用或模式定义来实现。例如，在 Python 中，开发者常使用 Pydantic 等库来定义数据模式。随后可将这些模式传递给模型，引导其生成与指定格式匹配的输出，如下所示。

结构化输出功能通过确保大语言模型的响应遵循预定义模式，显著简化了开发流程。这减少了后处理和验证的需求，让开发者能够专注于在其系统中使用数据。该功能提供类型安全，保证响应始终格式正确，同时无需借助复杂提示词就能获得一致的输出，整体上让开发流程更高效、更可靠。
